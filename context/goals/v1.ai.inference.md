## Task brief · v1.ai.inference · go-ai
Problem       docinfer's design found three things missing from go-ai v0.3.0
              that every caller restates. (1) No fake model endpoint is
              public: internal/aitest is a fixed-reply server plus go-ai's own
              format assertions, and infer, the spike and docinfer each wrote
              their own fake. (2) No accessor gives a response's output text:
              go-ai keeps three private copies, the spike a diverging fourth.
              (3) The client's transcription mode can't be read from the
              client and has no text form, so a cache key restates the mode
              or encodes an int. docinfer's library can't start until go-ai
              v0.4.0 exports these.
Behaviors     The public fake endpoint (package aitest)
              1. Serve starts a loopback endpoint whose API root ends in /v1,
                 closed when the test ends. It routes chat/completions,
                 embeddings, audio/transcriptions and models, each by a route
                 function the test gives, and records every request (method,
                 path, query, header, body) in order, safe for concurrent use.
              2. A route with no function answers 404 with an OpenAI-style
                 error body; a client sees an *ai.APIError of 404.
              3. Each route function gets the request's context, which ends
                 when the client cancels or disconnects and when the test
                 ends, plus its arrival number on that route, from 1.
              4. Chat Completions requests are decoded for the route
                 function: model, stream flag, max tokens, reasoning effort,
                 response_format schema name, and each message's role with its
                 text, images (media type, bytes) and audio (format, bytes),
                 beside the raw body. A body that doesn't decode answers 400.
              5. A typed chat reply encodes as Chat Completions: text or a
                 refusal; completed, or incomplete at length or
                 content_filter; usage. Through go-ai's completions client it
                 decodes to that Response.
              6. The same typed reply streams when the request asks: its text
                 in the chunks the test gives, then finish reason, usage and
                 [DONE]. It can break after a given chunk, which the client
                 sees as io.ErrUnexpectedEOF.
              7. An error reply gives any status, an OpenAI-style message and
                 an optional Retry-After written as given (seconds, an HTTP
                 date, or unreadable); the client's *ai.APIError carries them.
              8. The embeddings route function gets the model and inputs; its
                 typed reply of vectors and usage encodes as base64
                 little-endian float32, each vector at its index.
              9. The transcription route function gets the model, prompt,
                 language, file name, file bytes and other form fields; its
                 typed reply of text and usage encodes as the json format.
              10. The models reply is a list of whole JSON entries written as
                  given; go-ai's Models returns each id with the entry whole
                  as its Native.
              11. A raw reply on any route (Messages and Open Responses
                  included) writes the status, headers, and a JSON body or
                  SSE frames flushed one at a time, as given.
              12. A Gate parks requests: Wait parks a route function's request
                  until released or its context ends; Await blocks the test
                  until n are parked; Release lets n go; Open lets every
                  parked and later request go. A bound test proves exactly n
                  in flight with no sleep; a parked request whose client
                  cancels ends at once; the test's end never hangs.
              13. The package doc inventories its exported names and names no
                  caller of go-ai. It imports only the standard library and
                  go-ai's own packages; the base module still requires
                  nothing.
              OutputText, TranscriptionMode, go-ai's own tests, docs
              14. (*protocol.Response).OutputText returns every output_text
                  part of every Output message, in order, joined with nothing
                  between; never refusal, reasoning or function-call content;
                  "" when there is none. Chat-mode Transcribe and the quick
                  start use it, their outputs unchanged.
              15. (*ai.Client).TranscriptionMode() returns the client's mode.
              16. ai.TranscriptionMode's String and MarshalText give "route"
                  or "chat" (MarshalText refuses an unknown value);
                  UnmarshalText takes those and refuses any other name with an
                  error listing both. A mode in a JSON struct round-trips by
                  name.
              17. go-ai's own tests run against the public fake; the internal
                  fixed-reply server is gone, and the internal package keeps
                  only the format assertions and token counter. Every test
                  that passed still passes, and every asserted path holds.
              18. Docs: StreamIdleTimeout's doc says it also bounds the wait
                  for a stream's first bytes; the README lists aitest and its
                  candidates list drops the output-text helper and the
                  StreamIdleTimeout item; STANDARDS names public aitest as the
                  shared fake and the internal package as the format kit; the
                  base CHANGELOG gains a standing [Unreleased] section with
                  its compare link and records v0.4.0.
              infer, after the checkpoint
              19. infer requires go-ai v0.4.0, with no other requirement
                  change: chat output uses OutputText; the transcription mode
                  setting parses through TranscriptionMode's UnmarshalText,
                  its usage error still naming --mode,
                  INFER_TRANSCRIPTION_MODE, route and chat; its tests run on
                  the public fake, which replaces its own endpoint, and its
                  test package keeps only Builds, Halt and Env; every
                  command's output and exit status are unchanged; its
                  CHANGELOG records v0.3.1.
              Pending edits in the goal record
              20. The design Decisions on aitest and docinfer's design.md
                  (G3 and the API preamble, ~242-244, 514-516) are restated as
                  "public aitest built from internal/aitest's server and
                  infer's endpoint", replacing "export v0.3.0's existing
                  internal/aitest".
Test seams    - public aitest, driven through go-ai's ai.Client (completions,
                Embed, Transcribe in both modes, Models) and plain HTTP for
                404, 400 and raw replies
              - OutputText; TranscriptionMode's text methods and accessor
              - infer's commands run against the public fake
              - mise run check per module (GOWORK=off)
Slices        No upgrade slice: go-ai is current.
              Phase 1, branch go-ai, PR 1, then v0.4.0:
              1 OutputText, with chat-mode Transcribe and the quick start on it
              2 TranscriptionMode: accessor and text form
              3 public fake: Serve, recording, routes with 404, raw replies,
                typed embeddings, transcription and models replies, proven
                through ai.Client
              4 Chat Completions route: decoded requests, typed and streamed
                replies, broken streams, error replies with Retry-After
              5 Gate and route context
              6 go-ai's tests onto the public fake; internal server deleted
              7 docs and release prep; infer's slice 8 rehearsed under

## Decisions

- plan: tasks design → library → job → postgres → docinfer → acceptance, one session each; job split from library, which alone is docproc's library task's size.
- plan: fresh `init`, scaffolding only; library's first slice copies spike-ai-pipeline's docinfer at 6a631f1 in one commit, as go-ai and docproc did — rejected seeding init with the spike, so the design review precedes any code.
- plan: public under Apache-2.0, as go-ai and docproc.
- plan: each module (base, postgres, cmd/docinfer) starts at v0.1.0 on its own tags, the base tagged first; design assigns only the task that releases each tag.
- plan: docinfer sits in the templates' layer of the coordinator's `order`, the lowest above docproc and go-ai; joins `exclusive` after wave C.
- plan: docinfer's design note takes over docproc's layers.md docinfer sections; they retire at this goal's sync, not v1.ai.processing's.
- plan: acceptance reruns over v1.ai.processing's accepted ~/docs run, which completes 2026-11-19; no wait recorded.
- plan: docproc v0.3.0 already has everything docinfer reads and has made its removals, so the goal needs no docproc change.
- design: join of work in flight is docinfer's own claim table (claim(keys), one mechanism for single keys and batches; -race tests for leader cancelled, leader transient failure, waiter cancelled, leader panic, batch partly in flight) — rejected golang.org/x/sync/singleflight: it meets the waiter rule only through DoChan, a leader flag, the waiter's own ctx check and a retry loop, and Embed answers a batch of keys, so embeddings would need a second mechanism; the base module stays docproc + go-ai.
- design: a nested audio part's end of windows comes from docproc's plan record output (MediaAudioPlan, MediaVideoPlan), admitted as an input for its count; no window carries MetaCount (L19).
- design: no library defaults, as docproc: New and NewBounds refuse a value below 1 with ErrRequest; cmd/docinfer ships the operator's starting values (L24; settles layers.md's 512 KiB BatchBytes).
- design: a quarantined or failed part's outputs reach the model before the part's own event; the root's doc states consumers drop by that event, rather than job holding outputs (L6).
- design: Version joins Key's hash, and a held value that doesn't decode is a miss the next Put replaces; Cache keeps Get and Put (L18).
- design: an embedding is keyed by model and the chunk's SHA-256 alone, settings ""; the chunker stays in Profile (L16).
- design: the seam bound is derived per seam from MetaSeamBefore/After at Config.Join's words per second, no default (L20).
- design: library review round accepted L1–L5, L7–L13, L15, L17, L21–L27 and W1–W3 as the evaluation resolves them; L4 to docinfer, L15 to library and acceptance, the rest to library.
- design: go-ai exports a response's output text (a (*protocol.Response).OutputText method), and go-ai's transcribe.go, tools/infer and quick-start use it; docinfer keeps no helper (L14) — root fix in go-ai, per the architect: fix problems at their root, go-ai isn't blocked.
- design: go-ai exposes the client's transcription mode ((*Client).TranscriptionMode()), and docinfer's Identity reads it from the client — rejected a host-restated docinfer.Transcription field, which can disagree with the client and silently mis-key the cache (revises L13).
- design: go-ai exports aitest, a fake OpenAI-compatible endpoint (generate, stream, embed, transcribe, models; scriptable per request; hold until released) that docinfer's library and command tests use — rejected docinfer's own internal endpointtest (revises W2; C22).
- design: a new task, go-ai, runs between design and library and releases go-ai v0.4.0 (OutputText, TranscriptionMode accessor, aitest), tagged before docinfer's v0.1.0 — rejected go-ai slices inside library, already the goal's largest task.
- design: cmd/docinfer's report is per run, one page per input content, runs/<run>/report/index.html and <sha256>.html (docproc's file name), so the cross link is one relative path; schema "2" records each input's SHA-256.
- design: the report renders everything whole: the 1,000-rune cut goes; each source shown once as its chunks in order (index, span, a rejected chunk's error, no vector).
- design: the report shows an img beside each vision text at docproc's rundir.ContentPath and links to docproc's page; the run records the relative path to docproc's directory once; the file-URL branch goes (C17).
- design: each run's inferences (vision and transcription) are a per-run file appended per batch, beside the chunk record; the manifest stays small (C15).
- design: cmd/docinfer ships a per-endpoint transport ResponseHeaderTimeout (sized by vision's observed 38.9 s) and StreamIdleTimeout for extraction's stream; the library adds no deadline (C9, L12).
- design: "latest run" is docproc's Dir.Latest, the latest that ended; --run names any other (C4).
- design: command review round accepted C1–C24 as the evaluation resolves them, all to the docinfer task.
- design: a part's window group ends at whichever comes first: the window count of its audio plan record (MediaAudioPlan), the last window (no MetaSeamAfter) once every earlier index is in, or the end of Run's inputs — docproc v0.3.0's video plan record precedes its windows and holds no count, so it ends none (corrects the L19 line above, which named MediaVideoPlan).

- design: docinfer.New and job.New each take a Config struct, as dispatch.New does, since each needs more than four required inputs; NewBounds takes its four bounds positionally and returns (*Bounds, error) (construction-and-execution).
