## Decisions

- plan: tasks design → library → job → postgres → docinfer → acceptance, one session each; job split from library, which alone is docproc's library task's size.
- plan: fresh `init`, scaffolding only; library's first slice copies spike-ai-pipeline's docinfer at 6a631f1 in one commit, as go-ai and docproc did — rejected seeding init with the spike, so the design review precedes any code.
- plan: public under Apache-2.0, as go-ai and docproc.
- plan: each module (base, postgres, cmd/docinfer) starts at v0.1.0 on its own tags, the base tagged first; design assigns only the task that releases each tag.
- plan: docinfer sits in the templates' layer of the coordinator's `order`, the lowest above docproc and go-ai; joins `exclusive` after wave C.
- plan: docinfer's design note takes over docproc's layers.md docinfer sections; they retire at this goal's sync, not v1.ai.processing's.
- plan: acceptance reruns over v1.ai.processing's accepted ~/docs run, which completes 2026-11-19; no wait recorded.
- plan: docproc v0.3.0 already has everything docinfer reads and has made its removals, so the goal needs no docproc change.
