              dispatch then inference under the job's context, events

              through job. The root can't support job as built: Run
              pulls inputs on a goroutine of its own and never says when
              an input is admitted or when everything derived from it is
              out. So job can neither keep an output's event ahead of its
              results from one loop, nor know when a message is done.
              The spike has no job at 6a631f1, so job is new code.

Behaviors     The upgrade

              The root's additions
              2. Run yields Result.Input, the input itself, as it admits
                 each input, in pull order. It comes before anything
                 derived from that input: its inference, progress, and
                 the batches that hold its chunks.

                 nor a metadata text, such as a warning or a part's own
                 event: it yields Result.Input and then settles it, with
                 no work and nothing counted. Every input is echoed

              4. Run yields Result.Settled, the input's position in pull
                 order from 0, once everything derived from that input
                 is out:
                 - text, Markdown, metadata: its batches and its
                   extraction

                   extraction

                   echo
                 Each input settles exactly once, before Done. Tests

              5. Permanent reports dispatch.ErrRequest from a dispatch:
                 an input with neither or both of Path and Reader, an
                 input SHA-256 that isn't lowercase hex, or a resume
                 cursor that matches no message.
              Construction
              6. job.New takes a Config{Dispatcher, Pipeline,
                 CheckpointEvery}. It panics naming the field on a nil
                 Dispatcher or Pipeline. It refuses a CheckpointEvery
                 below 1, matching docinfer.ErrRequest; job declares no
                 error of its own. There is no default.
              Runner.Run
              7. Runner.Run dispatches the input and feeds each dispatch
                 event to the pipeline as one Input. The depth-0 part's
                 own event carries MetadataText's text of that part. Run
                 is fed every other event as it is, plan records
                 included. job loops over the pipeline's Run alone, and
                 yield is called from that loop's goroutine alone.
              8. Each Result.Input yields Update.Event, the dispatch
                 event, so updates keep one order:
                 - an output's update comes before its inference and
                   before the batches holding its chunks
                 - a part's update comes after its outputs', warnings'
                   and children's updates
                 Inferences, progress and batches yield as Update fields
                 as they are made. No output is held back until its
                 part's event.
              9. An inference's Text is put into the dispatcher's content
                 store under its TextSHA256 before its Update.Inference.
                 An inference with no TextSHA256 puts nothing. A failed
                 put stops the job with the error, not permanent.
              10. Options pass through to the pipeline. A refused
                  Extract fails before the dispatch starts: the stage is
                  never called.
              Checkpoints
              11. A message is the stretch of inputs that ends at an
                  output event with a non-zero After. The watermark is
                  the last such message whose inputs, and every earlier
                  input, have settled. job yields Checkpoint{After} with
                  that message's After once the watermark has advanced
                  by at least CheckpointEvery messages since the last
                  checkpoint, or since the start. It never yields the
                  highest After seen, and never one ahead of an
                  unsettled earlier input. An input with no store yields
                  no checkpoint.
              12. A dispatch resumed with Input.After set to a
                  checkpoint's After yields only the messages after it.
                  A test runs a crashed run's checkpoint through a
                  resumed run over the same index and content, and the
                  two runs' messages together are each message once.
              Done
              13. Done comes last, after the pipeline's Counts. Parts
                  counts parts by outcome at every depth, and Outputs
                  sums each part's Outputs. Both count each part ID once,
                  by its last own event. A test makes a replay miss
                  repeat a part: the part is counted once, under its
                  later outcome. Counts is the pipeline's, unchanged.
              14. Checkpoint and Done encode as {"after"} and {"parts",
                  "outputs", "counts"} under docinfer.Version "1", added
                  to and never changed. Update has no JSON of its own.
              Failures and cancellation
              15. A content miss, *docinfer.MissingError, drops the
                  index entry of its part under the part's SHA-256 and
                  its event's stage. The attempt then stops with the
                  error, alone and last. Permanent doesn't report it, and
                  a failed drop is joined to it. A redelivery prepares
                  the part again, and its run completes.
              16. Any other error the dispatch or the pipeline yields
                  stops the job, alone and last, keeping what Permanent
                  reads: dispatch.ErrSHA256 and dispatch.ErrRequest are
                  permanent; dispatch.ErrClaimLost and a store error are
                  not.
              17. A cancelled context stops the dispatch, the index
                  waits and claims, the join waits and the go-ai calls.
                  It yields ctx.Err() alone, last, and the dispatcher's

                  loop stopped early does the same, yielding nothing.
